Tutor flow diagram

This read-only diagram shows how one student message moves through the Tutor's workflow nodes. The highlighted start node runs first.

Reading the diagram

  • A plain arrow follows a node's next setting.
  • A labelled arrow is a possible switch_to branch.
  • Wait for student means the workflow pauses and resumes after another student message.
  • A terminal node has no outgoing route; its model output is returned to the student.
  • Dashed nodes cannot be reached from the configured start node.

Edit the workflow

Click a node to open its ID and YAML in the Node editor tab on this pane. You can rename the Node ID; references to it in start_node, next, and switch_to are updated automatically. You can also save or delete the selected node, or choose New node. YAML syntax is checked before writing. The complete Tutor is then checked and its validity is reported; an invalid Tutor remains editable but is unavailable to students.

Use the zoom controls when the workflow is large. All valid DAG transitions are placed from an earlier row to a later row, so arrows point downward.
